SSO / SAML

Single Sign-On via SAML 2.0 or OIDC with Azure AD, Okta, Google, or any compatible IdP.

{% endblock %} {% block content %}
Overview

Resource Planner supports SSO via python-social-auth (OIDC / OAuth 2.0) and djangosaml2 (SAML 2.0). Users are matched to existing accounts by email. First-time login creates an account automatically unless SSO_AUTO_CREATE_USERS=false.

Supported providers: Azure AD / Entra ID, Okta, Google Workspace, Auth0, any SAML 2.0 IdP.

OIDCOIDC / OAuth 2.0 Setup
  1. Register a new application in your IdP (Azure App Registration, Okta App, Google OAuth client).
  2. Set the Redirect URI to:
    https://<your-domain>/auth/complete/<backend>/ where <backend> is azuread-oauth2, okta-oauth2, or google-oauth2.
  3. Copy the Client ID and Client Secret.
  4. In Resource Planner, go to Settings → Integrations → SSO, enable the module, and fill in:
    • Provider — choose the backend
    • Client ID
    • Client Secret (stored encrypted)
    • Tenant ID (Azure only)
  5. Set the environment variables that python-social-auth expects:
SOCIAL_AUTH_AZUREAD_OAUTH2_KEY=<client-id>
SOCIAL_AUTH_AZUREAD_OAUTH2_SECRET=<client-secret>
SOCIAL_AUTH_AZUREAD_TENANT_ID=<tenant-id>
When SECRETS_SOURCE=aws, store these under a Secrets Manager secret and read them via a custom settings loader — the SSO module wizard fields serve as documentation only in that case.
SAMLSAML 2.0 Setup
  1. Install the SAML dependency:
    pip install djangosaml2 pysaml2
  2. Add djangosaml2 to INSTALLED_APPS and include its URLs.
  3. Export your IdP metadata XML from Azure (Endpoints → Federation Metadata) or Okta (Sign On → Identity Provider metadata).
  4. Upload the IdP metadata XML in Settings → Integrations → SSO → SAML Metadata.
  5. Download the Service Provider (SP) metadata from /saml2/metadata/ and register it with your IdP as a new application.
  6. Map attributes:
    urn:oid:0.9.2342.19200300.100.1.3 → email
SAML requires xmlsec1 to be installed on the server: apt install xmlsec1 (Debian/Ubuntu) or brew install libxmlsec1 (macOS).
AzureAzure AD / Entra ID Quick-Start
  1. Azure Portal → App registrations → New registration
  2. Name: ResourcePlanner, supported account type: Single tenant
  3. Redirect URI: https://<domain>/auth/complete/azuread-oauth2/
  4. After creation: Certificates & secrets → New client secret
  5. Copy the Application (client) ID and the new secret value
  6. Under Token configuration → Add optional claim, add email for ID tokens
  7. Under API permissions, ensure openid, email, profile are granted
  8. Paste client ID and secret into Resource Planner SSO settings
