Background Jobs

Resource Planner has a lightweight job runner at jobs/runner.py. Each job is a Python module with a run() → dict function registered in REGISTERED_JOBS. Jobs are triggered via the Jobs Admin API (service-token authentication) or the UI at Settings → Jobs.

Built-in jobs:

Job nameModulePurpose
todo_remindersjobs.todo_remindersSend due/overdue To-Do reminder notifications
jira_syncjobs.jira_syncPull sprints and issues from Jira
recharge_emailjobs.recharge_emailSend queued recharge forecast emails
wins_digestjobs.wins_digestSend weekly/monthly win digest emails
1Register a new job
  1. Create a module under jobs/, e.g. jobs/my_job.py:
    def run() -> dict:
        # ... do work ...
        return {'status': 'ok', 'processed': 42}
  2. Register it in jobs/runner.py:
    REGISTERED_JOBS = {
        ...
        'my_job': 'jobs.my_job',
    }
  3. Trigger it via the API:
    POST /api/v1/jobs/run/
    Authorization: Token <service-token>
    Content-Type: application/json

    {"job_name": "my_job"}
Set the JOBS_SERVICE_TOKEN environment variable to a strong random string. This token is required for all /api/v1/jobs/ endpoints.
2Scheduling with cron

Add entries to crontab -e on the server:

# To-Do reminders every 15 minutes
*/15 * * * * curl -s -X POST https://<domain>/api/v1/jobs/run/ \
    -H "Authorization: Token $JOBS_TOKEN" \
    -H "Content-Type: application/json" \
    -d '{"job_name":"todo_reminders"}'

# Jira sync every 30 minutes
*/30 * * * * curl -s -X POST https://<domain>/api/v1/jobs/run/ \
    -H "Authorization: Token $JOBS_TOKEN" \
    -H "Content-Type: application/json" \
    -d '{"job_name":"jira_sync"}'

Alternatively, use Celery Beat or Django-Q for more robust scheduling.

3Scheduling with AWS EventBridge
  1. Create an EventBridge Scheduler rule (cron or rate expression).
  2. Set the target to API Destination or Lambda that calls the job endpoint.
  3. For API Destination: provide the job URL, HTTP method POST, and attach a connection with Authorization: Token <service-token>.
  4. Add the request body {"job_name": "todo_reminders"} as a transformer or constant JSON payload.
  5. Grant the EventBridge role scheduler:CreateSchedule and events:PutTargets.
4Production deployment — Docker
# Build image
docker build -t resourceplanner:latest .

# Run with gunicorn
docker run -d \
  --name rp-web \
  -p 8000:8000 \
  -e DB_ENGINE=postgresql \
  -e DB_HOST=db \
  -e DB_NAME=resourceplanner \
  -e DB_USER=postgres \
  -e DB_PASSWORD_SOURCE=aws \
  -e DB_SECRET_NAME=resourceplanner/db/password \
  -e DJANGO_SECRET_KEY=<secret> \
  -e JOBS_SERVICE_TOKEN=<token> \
  resourceplanner:latest \
  gunicorn config.wsgi:application --bind 0.0.0.0:8000 --workers 4

Place a reverse proxy (nginx, Caddy, AWS ALB) in front on port 443 with TLS termination.

Run migrations as part of the startup or as a separate init container:

python manage.py migrate --noinput
python manage.py collectstatic --noinput
5Production deployment — bare metal / VM
# Install dependencies
pip install -r requirements.txt

# Set environment (use .env or systemd EnvironmentFile)
export DB_ENGINE=postgresql
export DJANGO_SECRET_KEY=<strong-random-key>
export DB_PASSWORD_SOURCE=env
export DB_PASSWORD=<db-password>

# Migrate and collect static
python manage.py migrate --noinput
python manage.py collectstatic --noinput

# Run with gunicorn (systemd unit recommended)
gunicorn config.wsgi:application \
  --bind unix:/run/resourceplanner.sock \
  --workers 4 \
  --timeout 120

Serve static files from STATIC_ROOT via nginx. Point /media/ to MEDIA_ROOT or use S3 with django-storages.
