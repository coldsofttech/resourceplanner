Jira Integration

Sync sprints and issues from Jira Cloud or Jira Server / Data Center.

{% endblock %} {% block content %}
Overview

The Jira integration lets Resource Planner read sprint boards, issues, and time-tracking data from your Atlassian instance. Data flows one-way (Jira → Resource Planner); no writes are made to Jira.

  • Import active and completed sprints by project key
  • Map Jira users to Resource Planner team members
  • Pull story points and logged hours for forecast comparison
1Create a Jira API token
  1. Go to id.atlassian.com → Security → API tokens.
  2. Click Create API token, give it a label like ResourcePlanner.
  3. Copy the token — you will not see it again.
  4. For Jira Server, use your account password or a Personal Access Token (PAT) from Profile → Personal Access Tokens (requires Jira 8.14+).
2Configure the integration
  1. Navigate to Settings → Integrations → Jira.
  2. Enable the module.
  3. Fill in:
    • Base URL — e.g. https://yourorg.atlassian.net (no trailing slash)
    • Email — the Atlassian account email used to generate the token
    • API Token — the token from step 1 (stored encrypted)
    • Project Keys — comma-separated Jira project keys to sync, e.g. RP,PLAT
  4. Save, then click Test Connection.
3Run the sync job

Syncing is handled by the background job jira_sync. Trigger it manually or schedule it:

# Via Jobs Admin UI
Settings → Jobs → jira_sync → Run Now

# Or via API (service token required)
POST /api/v1/jobs/run/
{"job_name": "jira_sync"}

For continuous sync, schedule this job every 15–60 minutes via cron or AWS EventBridge. See the Jobs & Deployment guide for details.

4User mapping

Resource Planner matches Jira users to team members by email address. If a Jira user's email doesn't match any team member, their issues are tracked as unassigned in reports.

Ensure team members in Resource Planner have the same email addresses as their Atlassian/Jira accounts for accurate attribution.
