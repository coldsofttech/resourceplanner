AI Integration

Connect an OpenAI-compatible model to Resource Planner.

{% endblock %} {% block content %}
Overview

Resource Planner's AI module connects to any OpenAI-compatible API — including OpenAI, Azure OpenAI, and self-hosted models via LiteLLM or Ollama. Once configured, AI powers:

  • Sprint forecast narrative generation
  • Smart suggestions on resource plans
  • Recharge email draft assistance
  • Natural-language search (future)
1Prerequisites
  • An OpenAI API key or an Azure OpenAI deployment with endpoint URL and key.
  • Django running with the configurations app installed (enabled by default).
  • Staff or superuser account to access Settings → Integrations.
2Enter your credentials
  1. Navigate to Settings → Integrations → AI.
  2. Toggle the module Enabled.
  3. Paste your API Key. It will be encrypted at rest (Fernet or AWS SM depending on your SECRETS_SOURCE env var).
  4. Set the API Base URL if using Azure or a custom endpoint, e.g.:
    https://<your-resource>.openai.azure.com/openai/deployments/<deployment>
  5. Set the Model field, e.g. gpt-4o or gpt-3.5-turbo.
  6. Click Save.
Never hard-code API keys in settings.py or commit them to source control. Use the UI or SECRETS_SOURCE=aws with AWS Secrets Manager.
3Verify the connection
  1. After saving, click Test Connection on the AI integration card.
  2. A green success banner confirms the model is reachable and the key is valid.
  3. A red error banner shows the HTTP status or network error — check firewall rules, proxy settings, or the key permissions.
4Azure OpenAI specifics

When using Azure OpenAI you must provide both the endpoint and the API version:

API Base URL: https://<resource>.openai.azure.com/
Model: <deployment-name>
API Version: 2024-02-01 # stored in the API Key field as JSON: {"key":"…","api_version":"…"}

Resource Planner's AI service reads AZURE_OPENAI_API_VERSION from the environment as a fallback.

5Self-hosted / local models

Any OpenAI-compatible server works. For Ollama:

API Base URL: http://localhost:11434/v1
API Key: ollama # any non-empty string
Model: llama3

Ensure the server is reachable from the host running Django. In Docker, use the service name or host network.

Troubleshooting
SymptomLikely causeFix
401 Unauthorized Wrong or expired API key Regenerate key in OpenAI dashboard and re-save
404 Not Found Wrong base URL or model name Check deployment name (Azure) or model slug
Connection timeout Firewall / proxy blocking outbound HTTPS Set HTTPS_PROXY env var or allow egress on port 443
Feature not appearing Module not enabled Toggle Enabled and save the integration card
